# Brainstorm: project-wide brand system

## 1. Какую пользовательскую проблему решаем

Сейчас разные маршруты выглядят как разные продукты: landing минималистичный, brief использует neon-cyberpunk, validation/admin опираются на стандартные Tailwind gray/blue/status colors, а modal-слои имеют собственные решения. Это снижает узнаваемость и доверие.

## 2. Current behavior

- Главная уже соответствует Pomelli brand book.
- Остальные экраны используют десятки сторонних hex и Tailwind palettes.
- Интерактивные слои описаны локально и не имеют общего focus/modal contract.
- Brief/report использует отдельную neon-тему с cyan, purple, amber, red и green.

## 3. Desired behavior

Все контролируемые проектом страницы и слои используют Inter, пять canonical цветов и opacity-варианты. Различия между landing, forms, reports и admin сохраняются через композицию, плотность, типографику и паттерны, а не через чужие palettes.

## 4. Ограничения домена

- Статусы reliability, ошибки и успехи должны оставаться понятными без зависимости только от цвета.
- Печатные отчёты должны сохранять читаемость.
- Нельзя менять API, данные, маршруты и бизнес-логику.
- Системные browser dialogs и UI сторонних сервисов вне контроля проекта.

## 5. Альтернативы

1. CSS override поверх старых классов — быстро, но оставляет скрытый дизайн-долг и непредсказуемый specificity.
2. Полностью переписать все страницы — чрезмерный риск для рабочих flow.
3. Ввести global tokens и хирургически заменить локальные цвета/слои — выбранный вариант.

## 6. Риски и неизвестности

- Потеря различимости semantic statuses после удаления red/green/amber.
- Контраст на тёмных report-экранах.
- Большой объём механических замен может затронуть print styles.
- Некоторые dynamic routes требуют данных и не открываются без fixture/ID; их проверка будет кодовая + build, а доступные публичные routes — browser QA.
