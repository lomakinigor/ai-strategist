# Spec: публичный демо-отчёт

## Problem statement

Пользователь не может оценить продукт до оплаты без запуска персонального исследования. Нужна публичная demo-страница, показывающая реальные возможности на обезличенном snapshot и не связанная с клиентской БД.

## User stories

1. Как новый посетитель, я хочу без регистрации увидеть исходные данные примера, чтобы понимать качество входа.
2. Как потенциальный покупатель, я хочу увидеть объём исследования и источников до AI-выводов.
3. Как собственник, я хочу открыть интерактивные выводы и полный отчёт, чтобы оценить практическую ценность.
4. Как владелец исходного кейса, я хочу, чтобы по демо нельзя было восстановить мою компанию или людей.

## Acceptance criteria

### A1. Публичный маршрут

- [ ] `/demo` доступен без авторизации.
- [ ] Страница не обращается к PostgreSQL и AI API.
- [ ] До отдельного одобрения страница имеет `noindex`.

### A2. Последовательность

- [ ] По умолчанию открыт шаг «Исходные данные».
- [ ] Второй шаг показывает покрытие: 48 фактов, 22 источника, 5 направлений.
- [ ] AI-результат открывается только после клика пользователя.
- [ ] На mobile все шаги доступны с клавиатуры и touch.

### A3. Результат

- [ ] Есть интерактивный обзор: позиция, узкие места, конкурентная картина, действия, roadmap.
- [ ] Есть отдельный полный отчёт со структурой §0–8.
- [ ] AI-блоки визуально маркированы «AI-интерпретация».
- [ ] Факты, гипотезы и недостаточные данные различимы.

### A4. Анонимизация

- [ ] Публичный snapshot не содержит `Репутация`, `glc-reputation`, исходный домен или исходное название.
- [ ] Нет email, телефонов, адресов, фамилий, ИНН/ОГРН и идентифицирующих URL.
- [ ] Конкуренты обозначены «Конкурент А/Б/В».
- [ ] Видна плашка об обезличивании и ограничениях кейса.

### A5. CTA

- [ ] Есть CTA «Получить отчёт по своей компании» → `/intake?tier=paid`.
- [ ] Есть вторичный CTA «Проверить свою компанию бесплатно» → `/intake`.

### A6. Качество

- [ ] TypeScript проходит.
- [ ] Production build проходит.
- [ ] Автоматический тест анонимизации проходит.
- [ ] Desktop и mobile проверены визуально.

## Affected files/modules

- `app/demo/page.tsx` — metadata и server page.
- `app/demo/DemoExperience.tsx` — переключение шагов и интерактивность.
- `app/demo/demo.module.css` — изолированная дизайн-система demo.
- `src/lib/demo/snapshot.ts` — статический обезличенный контент.
- `src/lib/demo/types.ts` — контракт snapshot.
- `src/lib/demo/__tests__/snapshot.test.ts` — безопасность/структура.

## Data model changes

Нет. БД не используется.

## API/state changes

- API не добавляется.
- UI state локальный: `input | research | report`, внутри report: `interactive | full`.
- URL клиента и `artifactId` не используются.

## Framing requirements

- Raw-данные и покрытие исследования идут раньше AI-summary.
- AI-summary открывается явным действием.
- Каждый AI-раздел имеет badge.
- Loaded language допустим только рядом с числовым/фактическим основанием.
- В footer есть trust-signal о data-first структуре.

## Negative scenarios and edge cases

- JS выключен: server page всё равно показывает вводную и честное описание; интерактивные вкладки требуют JS.
- Узкий экран 375 px: stepper не создаёт горизонтальный overflow.
- Длинные таблицы: внутри имеют controlled horizontal scroll.
- Старый клиентский JSON: не используется.
- Ошибка БД/AI: не влияет на demo.

## Test plan

1. Unit: snapshot содержит обязательные секции и валидные CTA.
2. Unit: сериализованный snapshot не содержит denylist и PII-patterns.
3. Typecheck.
4. Production build.
5. Browser smoke: первый шаг, переходы, interactive/full, CTA, 1440 px и 375 px.

## Rollback plan

Удалить `app/demo/` и `src/lib/demo/`. Другие маршруты, БД и API не затрагиваются.

## Out of scope

- CTA на landing.
- Переделка бесплатного персонального отчёта.
- Генерация нового отчёта из production-БД.
- Публичная индексация `/demo`.
- Аналитические события demo funnel.
