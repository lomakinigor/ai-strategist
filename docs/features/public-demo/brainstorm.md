# Brainstorm: публичный демо-отчёт

## Problem framing

Холодный посетитель должен заплатить 9 999 ₽, не увидев реальный интерфейс результата. Текущий бесплатный пробник требует заполнить анкету, дождаться research/LLM и зависит от совместимости сохранённого JSON. Нужен мгновенный, безопасный и честный способ понять продукт до оплаты.

## 6 вопросов

### 1. Какую пользовательскую проблему решаем?

Собственник или маркетолог хочет до оплаты увидеть: какие данные получает система, что она проверяет и как выглядит итоговый отчёт. Скриншотов и рекламных обещаний недостаточно.

### 2. Текущее поведение

- Hero ведёт сразу на оплату или в персональный бесплатный intake.
- Публичного demo flow нет.
- Существующий кейс ГПК «Репутация» хранится в клиентской БД и не должен открываться напрямую.
- Для одного сохранённого кейса доступны 48 фактов, 22 источника и исторический отчёт; готового актуального `interactiveJson` нет.
- Старый сохранённый `briefJson` может быть несовместим с текущим UI.

### 3. Желаемое поведение

- `/demo` открывается мгновенно без БД, авторизации и LLM-вызовов.
- Пользователь проходит три шага: исходные данные → покрытие исследования → результат.
- AI-интерпретация открывается только явным действием и маркируется.
- Все идентификаторы исходной компании удалены; публичный текст называет кейс ООО «Юридическая компания».
- Доступен интерактивный обзор и полный обезличенный отчёт.

### 4. Ограничения домена

- Нельзя публиковать клиентский UUID или обходить paywall.
- Нельзя оставлять названия, домены, телефоны, email, адреса, фамилии, реквизиты и идентифицирующие URL.
- Нельзя выдавать демо за гарантированный результат для любой компании.
- Snapshot должен быть детерминированным и не расходовать LLM-токены.
- Единственный дизайн-эталон — `O:/Projects/ai-strategist/Методологии/innodor-report.html`.
- `gpk-reputaciya-report.html` и PDF от 22 июня используются только как источники содержания; их оформление не переносится.

### 5. Альтернативы реализации

| Вариант                                     | Плюсы                                                 | Минусы                                        |
| ------------------------------------------- | ----------------------------------------------------- | --------------------------------------------- |
| Прямой публичный URL существующего artifact | Быстро                                                | Риск утечки, schema drift, БД/LLM-зависимость |
| Отдельная public-запись в БД                | Можно обновлять без deploy                            | Нужны флаг доступа, API и защита              |
| **Статический snapshot в коде**             | Безопасно, быстро, 0 ₽ за просмотр, легко тестировать | Для обновления нужен deploy                   |

Выбран статический snapshot.

### 6. Риски и неизвестности

| Риск                                          | Митигация                                                        |
| --------------------------------------------- | ---------------------------------------------------------------- |
| Остался идентификатор клиента                 | Автоматический denylist-тест + ручной просмотр                   |
| Демо выглядит как обещание результата         | Плашка «на основе одного реального исследования»                 |
| AI-summary создаёт framing bias               | Сначала raw-данные, затем явное открытие AI-выводов              |
| Дублирование paid-компонента создаёт coupling | Переиспользовать визуальные принципы и типы, не paid routing/API |
| Scope разрастается до redesign free-tier      | Free-tier и landing CTA вынести в следующие инкременты           |
